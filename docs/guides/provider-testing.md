# 测试 API 提供商与模型

<!-- markdownlint-configure-file { "MD013": { "tables": false } } -->

[返回使用指南](README.md)

提供商测试可以确认地址、凭据、模型和协议是否可用，并查看实际回复与耗时。

**测试会发送真实推理请求，可能消耗提供商额度。**
它使用该提供商已保存的配置，只请求选中的提供商，不自动重试或切换到其他提供商。测试不写入正常请求记录，本地请求用量统计也不包含这部分消耗。

## 测试一个模型

1. 在 **API 提供商** 列表中，点击提供商右侧的试管图标。
2. 选择已配置的模型，或手动输入模型 ID。尚未配置模型列表时也可以直接输入。
3. 选择测试协议，按需修改提示词和流式响应设置。默认提示词为 `Reply with OK.`。
4. 点击 **开始测试**，查看回复、HTTP 状态和耗时。

宽窗口中，左侧显示配置，右侧显示结果；窄窗口中，点击 **测试配置**
修改参数。测试不会修改模型列表、提供商启用状态或熔断状态。禁用的提供商也可以测试，便于确认连接恢复后再启用。

### 协议与账号要求

测试支持 Responses、Chat Completions、Completions、Anthropic Messages 和 Gemini
Generate
Content，但只显示该提供商已配置的原生或委托协议。配置为本地协议转换的能力不会出现在测试选项中。

Codex 订阅必须使用流式响应；Codex 和 Claude 订阅都需要先完成登录。修改地址、凭据或协议后，请先保存再测试。

## 批量测试模型

切换到 **批量模型**
后，可以搜索并勾选多个模型，也可以选择全部匹配项或清空选择。默认选中前 100 个已配置模型，每批最多测试 100 个。

要临时测试未配置的模型，在搜索框中输入模型 ID，再添加到本次测试。临时添加的模型不会写入提供商配置。

在 **测试配置**
中统一设置协议、流式响应、提示词和并发数。默认同时测试 2 个模型，可调整为 1 至 3 个。

测试过程中，列表会显示各模型的排队、测试和完成状态，以及首字总延迟、完整耗时。点击
**查看** 可打开某个模型的详细结果。

- **停止后续**：停止发出排队中的请求；已经发出的请求仍会完成并保留结果。
- **重试失败**：本轮完成后，只重试失败的模型，保留成功项的结果。

关闭测试窗口后，本次结果不会保留。

## 查看回复和原始响应

结果区可以切换 **预览 / 原文**，并复制当前视图。

| 视图 | 显示内容                                                     | 展示上限        |
| ---- | ------------------------------------------------------------ | --------------- |
| 预览 | 从响应中提取的回复，按 Markdown 显示段落、列表、代码块和表格 | 4096 个回复字符 |
| 原文 | 上游返回的原始响应正文，保留 JSON 或 SSE 事件格式            | 65536 个字符    |

超出展示上限或未完整接收时，界面会提示截断。原文中的凭据会脱敏，不包含响应头或完整原始请求。解析失败时，也可以查看返回的错误正文。

如果 Markdown 解析或渲染失败，回复区域会提示并显示原始文本，仍可关闭窗口或重新测试。旧版网关不支持原文时，界面会提示更新并重启网关。

## 如何理解耗时

| 指标       | 含义                                                                         |
| ---------- | ---------------------------------------------------------------------------- |
| HTTP 响应  | 从发送上游请求到收到响应头，包含连接、网络传输和服务端等待，不等于纯网络延迟 |
| 首字等待   | 从收到响应头到首段非空回复正文到达                                           |
| 首字总延迟 | HTTP 响应与首字等待之和，从发送上游请求开始计时                              |
| 完整耗时   | 从测试开始到响应读取和校验结束，还包含凭据准备等本地操作                     |

界面以秒显示耗时，保留两位小数，例如 `4.21 s`。点击 **耗时说明**
可以再次查看这些定义。

首字计时只用于流式响应，忽略心跳、空事件和思考片段。非流式响应无法测得首字；尚未到达或无法测量的阶段显示横线。即使后续失败，已经测得的阶段耗时也会保留。

## 为什么 HTTP 200 仍可能失败

HTTP 200 只表示上游返回了响应，不一定表示生成成功。以下情况也会判为测试失败：

- 响应中包含错误对象，或返回了 HTML 页面。
- 响应中没有可提取的文本。
- 流式响应缺少完成标记。

测试最长等待 60 秒，最多读取 1
MiB 响应。排查失败时，请结合失败原因和原文判断，不能只看 HTTP 状态。

## 通过控制接口测试

自行集成时，可以调用
`POST /control/v1/services/{service_id}/test`。此接口需要控制面认证，与客户端调用推理接口使用的访问令牌不同。

请求正文示例：

```json
{
  "protocol": "openai.chat",
  "model": "your-model-id",
  "stream": true,
  "prompt": "Reply with OK."
}
```

推理失败也会返回 HTTP 200 的测试结果，应读取结果中的
`ok`、`status_code`、`error_code` 和
`message`。请求格式、协议配置或服务 ID 错误则返回相应的 4xx 状态。接口中的耗时保留毫秒精度。

完整定义见[控制接口文档](../../contracts/control-api.openapi.yaml)。
