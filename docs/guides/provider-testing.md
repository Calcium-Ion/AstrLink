# 提供商测试

在「API 提供商」列表中，点击提供商右侧的试管图标打开测试窗口。
选择已配置的模型或手动输入模型 ID，选择测试协议，按需填写提示词、
切换流式响应，然后点击「开始测试」。默认提示词为 `Reply with OK.`。
宽窗口左侧配置、右侧查看结果；窄窗口点击「测试配置」修改参数。
结果区保持固定高度，回复单独滚动，可以切换「预览 / 原文」并复制当前视图。
「预览」显示提取后的回复；「原文」显示上游原始响应正文，保留 JSON 或
SSE 事件格式，解析失败时也可以查看错误正文。原文中的凭据会脱敏，
最多显示 65536 个字符，超长或未完整接收时提示截断。旧版网关不支持
原文时会提示更新并重启，不会使用提取后的文本冒充原始响应。

切换到「批量模型」可勾选多个模型，支持搜索、选择全部匹配项、清空选择，
也可在搜索框输入模型 ID 后添加到本次测试。默认选择前 100 个已配置模型，
每批最多 100 个；新增的测试模型不会写入提供商配置。
在「测试配置」中统一设置协议、流式响应、提示词和并发数；默认并发 2，
可选 1–3。列表实时显示各模型的排队、测试和完成状态，以及首字总延迟、
完整耗时。点击「查看」可查看该模型的详细结果、预览和原始响应。
「停止后续」停止发出排队中的请求，已发出的请求仍会完成并保留结果；
完成后可「重试失败」，成功项的结果保留。测试窗口关闭后不保留本次结果。

测试使用该提供商**已保存**的地址、凭据和协议配置，发送一次真实推理
请求，可能消耗提供商额度。支持 Responses、Chat Completions、
Completions、Anthropic Messages 和 Gemini Generate Content 的直接
原生或委托协议。配置为本地协议转换的能力不出现在测试选项中。
Codex 订阅必须使用流式响应；Codex 和 Claude 订阅都需先完成登录。
尚未配置模型列表时可以直接输入模型 ID。

结果包含成功或失败、HTTP 状态、分阶段耗时、提供商回复或失败原因：

- **HTTP 响应**：发送上游请求到收到响应头，包含连接、网络和服务端等待，不能视为纯网络延迟。
- **首字等待**：收到响应头到首段非空回复正文到达。
- **首字总延迟**：HTTP 响应 + 首字等待，从发送上游请求计时。
- **完整耗时**：从测试开始到读取和校验结束，额外包含凭据准备等本地操作。

界面统一以秒显示，保留两位小数（例如 `4.21 s`）；控制接口保留毫秒精度。
首字计时在读取 SSE 时记录，忽略心跳、空事件和思考片段。非流式响应
无法测得首字；未到达的阶段显示 `—`，已到达的阶段在后续失败时保留。
点击结果右侧「耗时说明」可查看口径。

回复按 Markdown 显示段落、列表、代码块和表格。内容解析或渲染失败时，
回复区域会提示并显示原始文本，弹窗仍可关闭或重新测试。
HTTP 200 本身不代表成功：错误对象、HTML 页面、没有文本的响应和
缺少完成标记的流都会被判为失败。测试最长等待 60 秒，读取响应上限
为 1 MiB，界面展示至多 4096 个回复字符和截断标记。凭据会从返回文本
中脱敏，不返回响应头或完整原始请求。

测试只请求所选提供商，不重试、不自动切换，也不修改模型列表、启用
状态或熔断状态。禁用的提供商也可以测试，便于修复连接后再启用。
测试不写入正常请求记录，因此本地请求用量统计不包含测试消耗。

控制接口：`POST /control/v1/services/{service_id}/test`，需控制面认证，
请求正文示例：

```json
{
  "protocol": "openai.chat",
  "model": "your-model-id",
  "stream": true,
  "prompt": "Reply with OK."
}
```

推理失败也返回 HTTP 200 的测试结果，客户端应读取 `ok`、
`status_code`、`error_code` 和 `message`；请求格式、协议配置或服务 ID
错误则返回相应的 4xx。接口完整定义见 `contracts/control-api.openapi.yaml`。
